# 読書記録アプリ(ReadingTracker)

個人の読書記録を管理する **PWA(Progressive Web App)** です。iPhoneのSafariで開いて
「ホーム画面に追加」すれば、ネイティブアプリのように使えます。

> **無料でずっと使えます。** ネイティブのiOSアプリと違い、Apple IDでの署名や
> 7日ごとの再インストールは一切不要です。ホスティングは GitHub Pages(無料)、
> データは端末内(ブラウザのローカルストレージ)にのみ保存されます。
> Mac も不要で、Windows PCだけで開発・公開が完結します。

---

## 1. 使い方(利用者向け)

1. iPhoneの **Safari** で公開URL(下記「3. 公開方法」参照)を開く
2. 共有ボタン(□に↑のアイコン)→ **「ホーム画面に追加」**
3. ホーム画面に追加されたアイコンから起動すると、アドレスバーの無い
   アプリのような画面で使える

> ⚠️ **必ず Safari で直接開いてください。** LINE・X(旧Twitter)・Instagramなど
> 他アプリ内の「アプリ内ブラウザ」で開くと、カメラ機能(バーコードスキャン)が
> 動作しないことがあります。リンクを受け取った場合は、右上の「…」などから
> 「Safariで開く」を選んでください。
4. データはすべてその端末のブラウザ内に保存される(他の端末やクラウドとは
   同期されない。バックアップ機能は今後実装予定)

## 3. 公開方法(GitHub Pages・無料)

このリポジトリはパブリックリポジトリなので、GitHub Pagesで無料・無制限にホスティングできます。

### 3-1. 初回のみ:GitHub Pagesを有効化する

1. GitHubでこのリポジトリの **Settings** タブを開く
2. 左メニューの **Pages** を開く
3. 「Build and deployment」の **Source** を **GitHub Actions** に変更する

これだけです。以降は `web/` フォルダに変更をpushするたびに、
[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml) が自動で
最新版を公開してくれます。

### 3-2. 公開URLの確認

1. リポジトリの **Actions** タブを開く
2. 「Deploy PWA to GitHub Pages」の実行結果を開く
3. 緑のチェック ✅ が付けば成功。実行ログの `deployment` ステップに表示される
   URL(通常 `https://<ユーザー名>.github.io/<リポジトリ名>/` の形)が公開先

このURLをiPhoneのSafariで開いて、「1. 使い方」の手順でホーム画面に追加してください。

## 4. プロジェクト構成

```
web/
├── index.html              # アプリ本体(エントリーポイント)
├── manifest.webmanifest    # PWAマニフェスト(アイコン・名前など)
├── service-worker.js       # オフラインキャッシュ
├── css/styles.css
├── js/
│   ├── app.js               # タブ切り替えなどアプリの起点
│   ├── db.js                 # IndexedDBラッパー(ローカル保存)
│   ├── models.js             # データモデル定義
│   ├── genreClassifier.js    # Cコード/NDC/キーワードからのジャンル自動判定
│   ├── openbd.js             # openBD API連携
│   ├── googleBooks.js        # Google Books API連携(フォールバック・検索)
│   ├── lookupCoordinator.js  # 上記をまとめて書誌情報取得〜表紙DLまで行う
│   ├── scanner.js            # カメラでのバーコードスキャン(ZXing)
│   └── views/                # 画面(本棚・追加・詳細・検索・スキャン)
├── vendor/zxing.min.js     # バーコード読み取りライブラリ(Apache-2.0)
└── icons/                  # ホーム画面アイコン
```

`ios-app/` には過去に作ったSwiftUIネイティブ版が残っています(現在はアーカイブ)。
詳細は [`ios-app/README.md`](ios-app/README.md) を参照してください。

## 5. データとネットワーク通信について

- 読書記録そのもの(タイトル・感想・評価など)は **その端末のブラウザ内にのみ保存**
  されます(IndexedDB)。サーバーへの送信は一切ありません
- 以下の機能は **ネットワーク通信が必要**です(それ以外はオフラインで閲覧・編集可能)
  - バーコードスキャン時・検索時の書誌情報取得(openBD / Google Books API)
  - 話題の本ページ(楽天ブックスAPI、実装予定)
  - 図書館所蔵検索(カーリルAPI、実装予定)
- 「ホーム画面に追加」したPWAは、iOSの「7日間操作が無いとサイトデータを消去する」
  仕組み(ITP)の対象外になるため、通常のブックマークで開くよりもデータが消えにくい
- ただし端末の初期化・アプリの削除・ブラウザデータの手動削除などではデータが失われる。
  機種変更や万一のトラブルに備え、エクスポート/バックアップ機能を今後実装予定

## 6. トラブルシューティング:カメラ(バーコードスキャン)が使えない

「バーコードでスキャン」をタップしてもカメラの許可ポップアップが出ない・映像が
映らない場合、以下を順に確認してください。エラー画面に表示される
`(NotAllowedError: ...)` のような詳細テキストも手がかりになります。

1. **Safariで直接開いているか確認する**
   LINE・X・InstagramなどのアプリからリンクをタップしてPWAを開くと、
   それらのアプリ内蔵ブラウザ(WKWebView)ではカメラAPIが正しく動作しないことが
   あります。「Safariで開く」を選ぶか、ホーム画面に追加したアイコンから起動してください。
2. **「カメラへのアクセスが許可されていません」と表示される場合**
   一度でも許可ダイアログで「許可しない」を選ぶと、次回以降ポップアップ自体が
   出なくなります。**設定アプリ → Safari → カメラ** で、このサイト
   (`bop88.github.io`)の設定を「許可」に変更してください。それでも直らない場合は、
   **設定 → Safari → 詳細 → Webサイトデータ** から該当サイトのデータを削除して
   もう一度開き直してください。
3. **「バーコード読み取りライブラリの読み込みに失敗しました」と表示される場合**
   画面を再読み込みしてください。改善しない場合は通信状況をご確認ください。
4. どうしても直らない場合は、手動入力または「タイトル・著者・ISBNで検索」から
   本を登録できます(バーコードスキャンは登録方法の一つに過ぎません)。

## 7. ローカルでの開発・動作確認(参考)

ビルド不要の素のHTML/CSS/JSなので、`web/` フォルダを静的サーバーで配信するだけで
動作確認できます(Python標準ライブラリの例)。

```bash
cd web
python -m http.server 8420
```

ブラウザで `http://localhost:8420` を開いて確認してください
(Service Workerの登録は開発用の簡易サーバーだと失敗することがありますが、
GitHub Pages上では問題なく動作します)。
